# Group 16 — Devices and session security

Implemented the device list behind the admin account menu and new-sign-in notification deep link. Admins can review the device, sign-in time, and IP; end one other session; or end all other sessions while keeping the current session. A completion state links to the password-reset flow. The existing `auth.sessions` deletion trigger records session ends in the audit log. A second Auth trigger now creates an in-app alert for every admin sign-in, and queues push/email only when the account opted into those channels. Each alert links to its exact session when still active; an ended session produces a clear fallback in the devices list.

The UI deliberately does not infer a city from an IP address or pretend to detect a unique physical device from a browser user-agent. The alert says "new sign-in" for that reason. When Auth has no useful device user-agent, it says so instead of inventing a device name. Supabase revokes refresh tokens when a session ends, but an already-issued access token can remain valid until expiry, so the UI does not promise immediate lockout.
